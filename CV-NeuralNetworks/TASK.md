# 5.6 Практическая работа

## Цель практической работы

Закрепить навыки построения и обучения свёрточных нейронных сетей.

## Что входит в работу

Необходимо решить задачу классификации на основе датасета рукописных символов EMNIST и оформить вашу модель как сервис. Таким образом, решение состоит из следующих шагов:

1. Подготовка данных, построение, обучение и тестирование модели.
2. Обёртка готовой модели в сервис, запуск веб-приложения в Docker-контейнере, подготовка репозитория.

---

## Задание 1. Подготовка данных, построение, обучение и тестирование модели

### Что нужно сделать

Скачайте архив practice-cnn.zip и разархивируйте его. Это будет ваша рабочая директория. Первым делом нужно инициализировать в ней Git-репозиторий. Для этого перейдите в директорию и выполните следующие команды:
```
git init
git commit -m "first commit"
```
Внутри вы найдёте пустой ноутбук prepare_model.ipynb. Ваша первая задача — заполнить его. Результатом заполнения ноутбука станет обученная модель распознавания рукописных символов, сохранённая в файл model.ckpt.

Точность вашей модели на валидационной выборке датасета должна быть не ниже 87%.

### Советы и рекомендации

- Обратите внимание, что нужный вам датасет уже скачан и находится в директории data/.
- Обязательно поэкспериментируйте с поиском лучшей модели. Попробуйте разные архитектуры, параметры свёрточных слоёв, глубину нейронной сети, добавление регуляризации, разные оптимизаторы и их параметры, batch_size и количество эпох обучения.

---

## Задание 2. Обёртка готовой модели в сервис, запуск веб-приложения в Docker-контейнере, подготовка репозитория

### Что нужно сделать

Вторым шагом нужно обернуть готовую модель в сервис и запустить её как часть веб-приложения для распознавания самостоятельно написанных символов. Само приложение уже готово, ваша задача — описать класс Model и всё, что может быть необходимо, в файле myapp/model.py. Объект этого класса должен хранить в себе вашу модель, загруженную из файла, а также иметь метод predict() для предсказания. Формат входных и выходных данных описан в комментарии.

Проверьте работу своего приложения, выполнив команду:
```
uvicorn myapp.main:app
```
Если всё работает правильно и точность предсказаний хотя бы 50% от ожидаемой точности, создайте Docker-образ и запустите приложение в Docker-контейнере с помощью команд:
```
docker build -t <your_app>.
docker run -p 8000:8000 <your_app>
```
Убедитесь, что и теперь всё работает, как ожидалось.

Когда всё будет готово, напишите небольшой отчёт о проделанной работе в файле README.md. Сопроводите его инструкциями по запуску своего приложения для проверяющего куратора.

Проверьте, что в коммит попадут все необходимые файлы и не попадёт ничего лишнего (логи, чекпойнты, кеш, данные для обучения и прочее), с помощью команды git status. Если вы следовали инструкциям, обновиться должны следующие файлы:

- prepare_model.ipynb
- model.ckpt
- model.py
- README.md

После этого загрузите свой репозиторий в систему Skillbox GitLab.

Ваше решение готово к проверке!

### Рекомендация

Вы можете заметить, что рукописные символы распознаются хуже, чем картинки из датасета. При желании попробуйте приблизить их к тем, на которых училась ваша модель. Возможно, вам пригодятся фильтры: Eroding and Dilating и Smoothing Images.

## Критерии оценки

### Принято:

- Готов ноутбук, в котором:
  - Правильно построена и обучена свёрточная нейронная сеть.
  - Выбрана корректная лосс-функция, с которой согласованы выходы модели.
  - На валидационной выборке точность по всем классам не ниже 0,87.

- Правильно описан класс Model:
  - Создание модели и загрузка чекпойнта корректны.
  - Предсказание возвращается в том виде, в котором его ожидает приложение.

- Приложение запускается локально и локально в Docker-контейнере.

- Написан понятный файл README.md, отражающий суть задачи, проделанной работы, и содержащий необходимые для запуска инструкции.

### На доработку:

- Данные не разделены или разделены неправильно на тренировочную и валидационную выборки.

- Слишком низкая точность модели.

- Не проведена или проведена некорректно предобработка данных на этапе обучения или инференса модели.

- Хотя бы на одном этапе неправильно выбран режим работы модели.

- Приложение не запускается.

- Нет отчёта и инструкций в файле README.md.
