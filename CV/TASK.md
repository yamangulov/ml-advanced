# 4.7 Практическая работа

## Цели практической работы
- Закрепить навык вывода изображения на экран и умение работать с изображением как с массивом.
- Подробнее изучить особенности задач компьютерного зрения, например работу с объёмом входных данных и их специфику, которая приводит к меньшей эффективности знакомых методов и моделей.

## Что входит в практическую работу
Необходимо решить задачу классификации на датасете рукописных символов EMNIST и оформить модель как сервис. Таким образом, решение состоит из следующих шагов:

1. Работа с данными, выбор, обучение и тестирование модели.
2. Обёртка готовой модели в сервис, запуск веб-приложения в docker-контейнере, подготовка репозитория.

---

## Задача 1
### Что нужно сделать

Внутри корневого каталога проекта вы найдёте ноутбук prepare_model.ipynb. Ваша первая задача — заполнить его, следуя указаниям. Результатом работы заполненного ноутбука будет обученная модель распознавания рукописных символов, сохранённая в файл model.pkl.

Точность вашей модели на тестовой выборке датасета должна быть не ниже 68%.

### Советы и рекомендации
Попробуйте применить как можно больше знакомых вам моделей для решения этой задачи классификации. Выберите ту, что даёт лучший результат. Вы также можете применить известные вам методы предобработки данных, например нормализацию.

---

## Задача 2
### Что нужно сделать
Вторым шагом нужно обернуть готовую модель в сервис и запустить её как часть веб-приложения для распознавания самостоятельно написанных символов. Само приложение уже готово, ваша задача — описать класс Model в файле myapp/model.py. Объект этого класса должен хранить в себе вашу модель, загруженную из файла, а также иметь метод predict() для предсказания. Формат входных и выходных данных описан в комментарии.

Проверьте работу вашего приложения, выполнив команду:
```
uvicorn myapp.main:app
```
Если всё работает правильно и предсказания делаются хотя бы с половиной от ожидаемой точности, создайте docker-образ и запустите приложение в docker-контейнере с помощью команд:
```
docker build -t <your_app> .
docker run -p 8000:8000 <your_app>
```
Убедитесь, что и теперь всё работает так, как ожидалось.

Когда всё будет готово, напишите небольшой отчёт о проделанной работе в файле README.md. Сопроводите его инструкцией по запуску вашего приложения для проверяющего куратора.

Убедитесь, что в коммит попадут все необходимые файлы и не попадёт ничего лишнего (логи, чекпойнты, кеш, данные для обучения и прочее), с помощью команды git status. Если вы следовали инструкциям, обновиться должны следующие файлы:
- prepare_model.ipynb
- model.pkl
- model.py
- README.md

После этого загрузите репозиторий в систему Skillbox GitLab. Теперь ваше решение готово к проверке.

### Советы и рекомендации
Если вы как-то предобрабатывали данные перед обучением модели, обязательно добавьте такую же предобработку в класс Model, чтобы предсказания были корректными.

## Критерии оценки
### Принято:
1. В ноутбуке выполнены все микрозадания: «Выведите размер датасета», «Выведите примеры изображений из датасета» и «Какие символы чаще всего путает модель?».
2. Верно проведено преобразование данных из матриц в векторы.
3. Корректно выбрана и обучена модель, соответствующая типу задачи. На тестовой выборке точность по всем классам не ниже 0.68.
4. Правильно описан класс Model, в методе predict соблюдены все размерности.
5. Приложение запускается локально и локально в docker-контейнере.
6. Написан понятный README, отражающий суть задачи и проделанной работы и содержащий необходимые для запуска инструкции.

### На доработку:
1. Пропущены микрозадания.
2. Слишком низкая точность.
3. Ноутбук заполнен верно, но приложение не запускается.
4. Всё сделано верно, но нет отчёта и инструкций в README.
